
# PathSnap final evaluation: two-laptop setup

## Included evaluator data
`data/evaluator_test/` contains the 10 trips supplied for final evaluation:
00000015, 00000017, 00000023, 00000030, 00000049, 00000059, 00000067, 00000073, 00000087, 00000094.

The final-evaluation backend is configured to list these trips when launched with
`START_BACKEND_EVALUATOR.bat`. It does not return `.route` reference labels or evaluation
metrics to the browser. The inference endpoint loads the GPS track and road network but
does not read the reference route file.

## Laptop 1 — backend
1. Copy/extract the complete `PathSnap_Evaluator_Ready` folder to Laptop 1.
2. Ensure Python 3.11 is installed.
3. Open PowerShell in the project folder and run (once):
   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
   If already installed, skip these commands.
4. Run `START_BACKEND_EVALUATOR.bat`.
5. In another PowerShell window, run `ipconfig` and note the active Wi-Fi adapter's
   IPv4 Address (for example `192.168.1.25`). Do not use `127.0.0.1` for Laptop 2.
6. Keep the backend terminal open. If Windows Firewall asks, allow Python/Uvicorn on
   Private networks. Both laptops must be on the same Wi-Fi/hotspot network.
7. Test on Laptop 1: `http://127.0.0.1:8000/health` and
   `http://127.0.0.1:8000/trips`. The trips response should contain the 10 evaluator IDs.

## Laptop 2 — frontend
1. Copy the `frontend` folder to Laptop 2 (or copy the whole project folder).
2. Install/use Python 3.11, open PowerShell in the folder containing `frontend`, then run:
   ```powershell
   py -3.11 -m http.server 5500 --directory frontend
   ```
   If your terminal is already inside the `frontend` folder, use:
   `py -3.11 -m http.server 5500`.
3. On Laptop 2, open `http://localhost:5500`.
4. In the API URL field on the page, enter:
   `http://<LAPTOP-1-IP>:8000`
   Replace `<LAPTOP-1-IP>` with Laptop 1's actual IPv4 address, e.g.
   `http://192.168.1.25:8000`.
5. Select a trip and click **Reconstruct route**.

## Network checks
- Both laptops must be on the same LAN/Wi-Fi/hotspot; guest Wi-Fi may block device-to-device traffic.
- The backend must be started with `--host 0.0.0.0`, not the default localhost binding.
- If Laptop 2 cannot connect, check Windows Firewall inbound access for TCP port 8000
  on Private networks and verify the IP address has not changed.
- From Laptop 2, open `http://<LAPTOP-1-IP>:8000/health`. It should return JSON
  with `"status":"ok"` and `"model_loaded":true`.
- Then open `http://<LAPTOP-1-IP>:8000/trips`; it should list the evaluator trip IDs.

## Important evaluation integrity
- Use `student_test` for development only.
- Use `evaluator_test` only for the final demonstration/evaluation.
- The API inference path does not read the evaluator `.route` file and does not expose
  reference labels. Do not use evaluator routes to tune, retrain, select models, or
  change decoder settings.
- Predictions are generated by the trained model and Viterbi decoder from each selected
  trip's GPS observations and road network.
